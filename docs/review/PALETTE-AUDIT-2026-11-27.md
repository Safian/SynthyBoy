## 1. Where the catalogue palette comes from
- FACT: the nine swatches are a HAND-WRITTEN list, `components/colors.json` key `"palette"` (lines 265-300): nine `{token,label}` entries (button.surface, button.border, accent.green, accent.red, text.icon, accent.cyan, radio.active.text, radio.surface.top, radio.text). - FACT: `scripts/gen-native-component-catalog.py:185-188` loops `components.style.palette()` (components/style.py:`palette()` = deepcopy of that list), resolves each token via `color()` and writes `<span class="swatch">label - #HEX</span>` into `{{PALETTE}}` of `scripts/templates/native-component-catalog.html:42-44`. Output: docs/ui-components/kepes-katalogus.html (generated, marker line at top).
- FACT: it is NOT derived from usage. The nine are the colours of the button / radio_button / ActiveText components (radio.* tokens are read only by components/native/radio_button/radio_button.py and scripts/mpc-skin-extras/99_ui_screen_lfo.py). Nothing checks the list against the other 251 tokens or against the screens.
- FACT: labels are Hungarian role names typed by hand; 'Aktiv hatter' = accent.cyan (flat), but the real active button is a vertical gradient (see section 3).

## 3. Colours that actually appear on screen
Method (shots2.py / agg2.py): 42 images = 16 current docs/screens/*.jpg (non _old; 3 of them, fx/master/voice, are 1280x628 page-only crops) + 4 docs/screens/*_old.jpg + 10 key61/*.png + 12 xl/*.png (old UI, /private/tmp/claude-501/old-shots, sampled evenly out of 136/188). Crop rows 108..738 (the host header and host function bar are excluded; they are not our palette). Only 'stable' pixels counted (3x3 neighbourhood within 8 per channel for surfaces; >=2 similar neighbours within 10 for ink) to cut anti-aliasing; surfaces (max channel < 90) and ink (>= 90) are quantised separately (step 4, greedy clusters radius 5 / 10), then merged across images (radius 6 / 12). Shares are % of the crop pixels, averaged over the images of the set; pages = images where the cluster occurs. Distance = Euclidean RGB to the nearest of the 260 tokens.
LIMITS (HYPOTHESIS where noted): (a) the old-shots set is the OLD UI package, not the current one; the current set is only 16 images. (b) The newest dial filmstrips (commit 7f16db44, 2026-11-26, flow gradient) are not in the 11-25/26 screenshots: the value arcs there are a single light blue ~#64c7fd, which matches no token (nearest mod_targets.border.active #72d1ec d=24; dial.value #4c8dff is d~45). The code path (components/native/level/level.py:255-267) draws the 4-stop flow gradient cyan #2ee6f0 -> #6c7bff -> #b45cff -> #ff4fc3, so the screenshots are stale for dials (HYPOTHESIS: needs a fresh device capture). (c) Thin 1-2 px strokes (env curve, key curve) are under-counted by the stability filter; direct pixel sampling was used to confirm them. (d) JPEG (docs/screens) shifts hues by a few units; the device palette also looks ~1-2% darker (#fec23e vs #ffc23d).
