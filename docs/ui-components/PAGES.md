# How a page is put together

A page is a class that owns a library screen (or a few components), reads the instance, binds controls to parameters, routes touch, and publishes its Q groups. `shell-mpc/overlay/voice_ui.h` (`VoiceUi`) is the smallest complete example; read it next to this file. The other pages (`mixer_ui.h`, `master_ui.h`, `macro_ui.h`, `fx_ui.h`, `filter_ui.h`, `env_ui.h`, `lfo_ui.h`, `mod_ui.h`, `osc_ui.h`) follow the same pattern.

## 1. PageView and the Ui class
`shell-mpc/overlay/page_view.h`: `template <class Ui> class PageView final : public IView`. It draws the ground of the tab (`page::ground`), keeps a hash of the scene to know when the picture changed, clips the strip of the host's Q-Link panel (`ViewInput::panelEdgeX`), and calls your class. Constants `page::kW` 1280, `kH` 800, `kTabY` 110, `kTabH` 628 (the tab is 1280 x 628 at y 110). `page::Input { live, targets, instance }` is what the controller hands the page besides the instance.
Your `Ui` class must have (copy `VoiceUi`):
| Member | Meaning |
|---|---|
| `static constexpr int kElementPage` | the `UiStack` id of the page (1 oscillator, 2 envelope, 3 LFO, 4 filter, 5 mixer, 6 FX, 7 mod, 8 macros, 9 master, 10 voice: pick a free number) |
| `void update (IInstanceView&, const UiStack&, double nowMs, const page::Input&)` | read the instance into the components, publish the Q group |
| `void draw (gpu::SceneBuilder&) const` | the page: ground excluded, popups and live parts included |
| `bool touch (const TouchEvent&, UiStack&, IInstanceView&, double nowMs)` | route a finger; return true when the page took it |
| `bool wheel (int x, int y, int notches, UiStack&, IInstanceView&, double nowMs)` | the mouse wheel; use `top->wheelOver (x, y, notches, ch)` |
| `void tick (double nowMs, UiStack&, IInstanceView&)` | forward `tick` to the component that holds the gesture (long press) |
| `bool fingerDown() const noexcept`, `void dropGesture() noexcept` | gesture state |
| `void forgetQGroup() noexcept` | called when the page is shown: reset the active group and `QSlots::forget()` |
| `int topPage() const noexcept` | the id of the top page of the stack (status file) |
| `const int* qTargets() const`, optional `int qSlotCount() const` | the published Q slots (16 when `qSlotCount` exists, else 4) |
Register it: `shell-mpc/overlay/pages.h` (`using VoicePage = PageView<VoiceUi>;` and a `case layout::kKindVoice` in `make`), a view kind in `shell-mpc/overlay/overlay_layout.json` (the region and the marker colours; `overlay_layout.h` is generated by `scripts/gen-overlay-layout-header.py`), and the skin (`scripts/mpc-skin-extras/83_pages.py`) which hides the host widgets under the page.

## 2. Binding controls to parameters (ui_bind.h)
`shell-mpc/overlay/ui_bind.h`, namespace `synthyboy_mpc::overlay::uibind`. Pure functions, no state; they bind to SynthyBoy's parameter table (see [REUSE.md](REUSE.md)). The "bind types" are an enum local to each page (`enum class T { Knob, Number, Toggle, Stepper, List, GridStep, Inert }` in `VoiceUi`; `Field`, `Select`, `Pick`, `Graph` in `EnvUi`) plus an `Item { id, component, type, key, param, ... }` table built by `bind (id, &component, T::..., "engine.key")`:
| `T` | `pull` (update) | `handle` (a change) |
|---|---|---|
| `Knob` | `state.value = state.modValue = uibind::normOf (param, plain)`, `defaultValue`, `valueText` from `uibind::formatValue` | `Value` -> `uibind::writeNorm (inst, param, c.value)` |
| `Number` | `state.value`, `min`, `max`, `step`, `defaultValue` from the parameter | `Index` -> `uibind::writePlain (inst, param, c.index)` (or `c.value`) |
| `Toggle` | `state.on = value > 0.5` | `Index` -> `writePlain (index)` |
| `Stepper` | `count`, `index`, `setItem (choices[index])` | `Index` -> `writePlain`; `Request` -> open a `ListPopup` |
| `List` (LedList) | `setOptions (choices, n)`, `state.index` | `Index` -> `writePlain` |
| `Inert` | nothing | the page handles it itself (selectors, virtual targets) |
The helpers: `indexOfKey (key)` (table index, -1 none), `info (idx)`, `normOf (idx, plain)`, `writePlain (view, idx, plain)` (constrains, normalises, writes), `writeNorm (view, idx, norm)`, `formatValue (info, plain, out, cap)` (units: "35%", "420 Hz", "-6.0 dB"; a value that rounds to zero has no sign; a ".pan" key reads C, L 50, R 50), `noNegativeZero`. Modulation helpers: `sourceName`, `shortName`, `shortSourceName`, `isMacroSource`, `macroSource`, `sourceGroup`, `fillSourceBoard (ModSourceBoard&)`, `modsOf (view, param, selected, rows)` (the `ModInput` of a parameter from the matrix), `slotOf`, `freeSlot`, `slotsOfSource`, `slotOfPair`, `DestIndex::get()`, `envSource`, `lfoSource`, `boardLabel`, `boardColourName`.
Rule: the page writes ONLY through `IInstanceView::writeParam` (via `writePlain` / `writeNorm`); the next `update` reads the value back and shows it. Never write `state` as the answer to a change.

## 3. Q groups, reading order, 16 slots
A Q group is four values (a block of the screen, a strip, a row, a bank): `QGroup` ([qgroup.md](qgroup.md)). Rules:
- Order the groups of a page in READING order (left to right, top to bottom); 1 to 4 members per group, chips 1 to 4 in reading order.
- The page has 16 Q slots (`QRouter::kCount` = 16: `kGroupSize` 4 x `kGroups` 4). Slots 1 to 4 are the ACTIVE group; 5 to 8, 9 to 12, 13 to 16 are the next groups in reading order, wrapping, each once. A page with fewer groups leaves the rest without target.
- Publish them in `update` with `QSlots::publish (inst, nGroups, active, [&] (int group, int* four) { four[i] = table index or -1; })` (`shell-mpc/overlay/q_publish.h`). It tells the instance only when a slot changed. `QSlots::forget()` when the page is shown again.
- Tell each group its block so its idle chips show the knob numbers: `QGroup::setBlock (QRouter::blockOfGroup (nGroups, active, g))` (or `setBlocks`, `usedGroups`, `setRowBlocks` for list pages). `QGroup::setWideDevice` is set once by the overlay (16 knobs on the XL, 4 on the Key 61).
- A target can be a virtual value of the page (`QRouter::encode (id, QRouter::kVirtual)`, `inst.setQVirtual`, `inst.takeQVirtual`): the step and row selectors of the Voice page.
- A touch that goes down on a member makes its group the active one.
- On the device a hardware knob turn reaches the PARAMETER (Q router, stepped targets are driven relatively) and the page shows it on the next `update`; `QGroup::turn` / `turnQ` is the path of the tests and of components used without the router. A page must therefore keep the Q slots and the controls in step.
Tests: `shell-mpc/overlay/tests/qslots_host.cpp` (the published list of every page), `shell-mpc/tests/q_router_host.cpp`.

## 4. The stack: detail pages and popups
`UiStack` (`shell-mpc/overlay/ui_stack.h`): main -> full (`openFull (element)`) -> detail (`openDetail (page)`), at most `kMaxDepth` = 8 (one full page and seven detail pages), `back()`, `closeAll()`, `depth()`, `isMain()`, `top()`, `id (i)`. The page ids are yours (`enum Page { kPageList = 15 }`). A stepper's `Request` opens a popup: fill a `ListPopup` (`state.items`, `count`, `current`, `showCurrent()`), `stack.openDetail (kPageList)`; the popup's `Index` change writes the parameter and calls `stack.back()`; a `Request` with the backdrop id also calls `stack.back()`. Draw the popup LAST in `draw` while `pageTop_ == kPageList`; route touches to the top component (`topComponent()`). The stack is closed by the controller when the instance's page leaves the screen; it is not saved.

## 5. Live drawing (drawLive)
Anything that moves every picture is drawn outside the cached cells: `display::drawLive`, `lfodisplay::drawLive`, `EnvCompact::drawLive`, `EnvFullScreen::drawLive` (running dots, cursors, read heads, grains, meters, the spectrum). Call `draw (sb)` first, then the live part. A live part must not draw under the list popup (the Env and LFO pages skip it while the popup is open). Draw a value that changes every picture only when it changed within the last third of a second as part of the cached cell (`cached = false`), so the cell layers under it do not redraw each picture.

## 6. Cached cells
`Cell (sb, rect, pad)` ([core.md](core.md)): the helper keeps what a cell drew from one picture to the next and redraws it only when its content or rectangle changed. Rules: every leaf draws in one cell (`Component::draw` does it); a `Composite` has one for its under-drawing and one for its over-drawing; ONE CELL PER Q CHIP (`QGroup::chip` opens a cell of the chip's own rectangle, because the chips of a group are far apart); the ground of a tab is a cell. A cell must start and end with the default style and paint, contain everything drawn inside, and have no Clear, Clip or Feedback. Details: docs/MPC.md "Cached cells and layers". Tests: `cell_plan_host`, `cell_cache_host`, `gpu_scene_host`.

## 7. The layout lint
`shell-mpc/overlay/tests/layout_lint_host.cpp` builds every page in the states of the UI gallery (Init and every factory preset, sub-pages, detail pages, every FX type and page, both macro banks, both Master sides, the LFO modes, the editors) and checks the component tree and the scene. A page must pass:
| Rule | Meaning |
|---|---|
| a | two interactive controls (leaves) overlap |
| b | a touch rectangle smaller than 56 px in one direction (`touchTargets` is used: a component with inner cells must override it) |
| c | a control or a Q / modulation chip not fully inside the drawing region (the tab, 1280 x 628) or not inside its parent |
| d | text cut with an ellipsis, wider than its cache cell or its control, outside the region, or two texts overlapping |
| e | a Q chip or modulation tab covers the arc or the handle of a knob |
| f | the same id (= the same engine parameter) on two interactive controls of one page |
| g | a titled block with less than half of its area covered by its children |
| h | more than three distinct knob diameters on one page |
Exit code 0 only when every finding is in `layout_lint_baseline.json` (empty today) and every baseline entry still occurs; `--self-test` checks the checks. A new finding fails the test: fix the layout, do not add to the baseline.

## 8. Checklist: adding a new page
1. Write the screen in `shell-mpc/ui/<name>_screen.h` (a `Composite`, built only from library components; one table of Q groups; every control >= 56 px; `minSize()` = the tab 1280 x 628). Include it from `ui.h` if generic.
2. Write the interface test first in `shell-mpc/ui/tests/` (one `ui_cov_*`-style file or `ui_<name>_host.cpp`): every gesture gives the documented change, ends clamp, nothing when disabled, the gesture is kept outside the rectangle, drawing inside the rectangle at the minimum and a large size, `QGroup::check` is 0.
3. Write the Ui class `shell-mpc/overlay/<name>_ui.h` after `voice_ui.h`: ids enum, `T` table, `configure`, `pull`, `handle`, `publishQGroup`, `touch`, `wheel`, `tick`, `draw`.
4. Register the view: `overlay_layout.json` (a new kind and markers), regenerate `overlay_layout.h`, add `kKind...` and the `case` in `pages.h`, the skin script `scripts/mpc-skin-extras/83_pages.py`.
5. Add the page to the gallery tests (`ui_gallery_host.cpp`, `ui_gallery_extra_host.cpp`), `coverage_host.cpp` (every engine parameter reachable), `qslots_host.cpp` (the published groups), `layout_lint_host.cpp` (the states).
6. Update docs: docs/MPC.md "Q proxies" table of groups, the user guide picture list, this folder.

## 9. Checklist: adding a control to a page
1. Pick the component by the table in [README.md](README.md). Add it to the screen as a public member, place it in `layout()` (min size respected, 16 px lane above a Q member for its chip).
2. Put it in a Q group (or leave it out on purpose: say why), keep the group adjacent and in reading order.
3. In the Ui class: `bind (id, &screen.member, T::..., "engine.key")` and add the id to the enum; `pull` reads, `handle` writes.
4. Publish the new Q target in `publishQGroup`.
5. Run (the integration session, not the worker): the screen's interface test, the page's host test, `coverage_host`, `qslots_host`, `layout_lint_host`, the gallery render.
Files touched: `shell-mpc/ui/<screen>.h`, `shell-mpc/ui/tests/...`, `shell-mpc/overlay/<page>_ui.h`, possibly `choice_names.h`, the page's test in `shell-mpc/overlay/tests/`.
