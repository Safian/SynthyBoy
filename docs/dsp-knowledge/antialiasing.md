# Anti-aliasing

Plan: `docs/plans/distortion-antialiasing.md` (owner decisions D1-D5, 2026-11-21).

## Facts

- First-order ADAA on the distortion: Zero-Square (type 9) gains **5.91 dB** alias reduction at
  drive 0 where the plan's model said 10.1 dB; the kernel matches a double-precision reference,
  so the model was optimistic. Acceptance threshold for every type: >= 3.0 dB.
  `test: core/tests/test_own_alias_dist_tanh.cpp`
- ADAA lowers the wet-path treble (about -2.4 dB at 10 kHz, derived); the remedy is 2x
  oversampling (stage C, D1: on XL/desktop only, 15 samples latency), not a compensation filter.
- Quantize ADAA: for a segment shorter than 1/1024 use the exact staircase average, not the
  midpoint level (error 0.0276 -> 1.7e-4). `test: own_alias_warp_* (fix 6085f61f)`

- **ADAA has a half-sample delay and a Nyquist zero** in the linear regime (`(x[n]+x[n-1])/2`); Vicanek (2023/24) moves the kernel by half a sample: one sample delay, only 6 dB loss at Nyquist, and a one-pole pair `a = 1/(3+sqrt 8)` makes it exactly transparent. `source: sources.md (Vicanek, Parker et al. Sec. 4)`
- **ADAA alone is weak at high-frequency aliases; ADAA + 2x-4x oversampling is the robust combination** (Vicanek Sec. 4; Zavalishin 6.13: 44.1 kHz is "usually insufficient"). This supports D1 (2x on XL/desktop). HYPOTHESIS to test: Vicanek's half-sample-shifted kernel instead of plain first order on tier low (no oversampling there).
- **Inside zero-delay feedback loops** the half-sample delay must be absorbed into the following trapezoidal integrator (Parker et al. Sec. 6, Zavalishin 6.13); relevant if a filter saturator gets ADAA.

- **X-Shaper (types 12, 13) with ADAA (X2, X3):** steep curve, alias -36.83 dB naive to -42.96 dB with ADAA (-6.14 dB), harmonics unchanged (2.62 / 2.60 dB). `measured: 2026-11-21, Mac, Release, batch 4 merged tree; test: core/tests/test_own_alias_dist_shaper.cpp (DIST-AA type=12), test_own_alias_shaper_engine.cpp`. Types 0-11 keep their checksums bit for bit (DIST-AA-CHECKSUM lines of the five alias tests differ only at types 12 and 13).
- **Library oscillators L1 (host rate):** Sample type, note 84: Hard Clip -5.24 dB alias (-42.05 to -47.30), Quantize -8.50 dB (-22.45 to -30.95), harmonics within 0.03 dB. `measured: same run; test: core/tests/test_own_alias_lib_warp.cpp (LIBWARP-AA)`. Without warp nothing changes (bits).
- **Oscillator warps O2 (sample-domain warps in WtOsc, ADAA):** note 84, 4x: Zero Square 29 -9.73 dB, Quantize 3 -12.39 dB, 2x (lowWarp): -15 to -20 dB; harmonics within 0.1 dB. `test: core/tests/test_own_alias_warp_adaa.cpp (WARP-AA)`. `WARP-CHECKSUM aa=off` of all 52 types is bit-identical to the code before O2; `aa=on` differs from `aa=off` for 20 types: the 15 sample-domain ones (3, 27-40) and the five with events (Sync 1, Pulse 6, Sync Var 11, Flip 18, Mirror 19) that O3/O4 change on purpose.
- **O3 PolyBLEP at the master wrap (Sync 35 %):** alias drops 14.5 to 26.3 dB (notes 60 to 96, 2x and 4x), harmonics within 0.05 dB; the 2x-against-4x difference at note 60 is -14.23 dB off and -14.25 dB on, so the residual does not close the gap between the two rates. **O4 PolyBLAMP:** Mirror 80 % -19.9 dB, Flip 50 % -17 to -18.6 dB, Sync 35 % with BLEP+BLAMP a further 7 to 17 dB below BLEP alone. **Pulse 50 %** was -2.93 / -2.97 dB (notes 72 / 84) while `warpEvents` had only the clamp slope jump; with the second slope jump at phase 0 (the slope rises from 0 again at the wrap; the value is continuous) it is -16.82 / -18.52 dB (measured: 2026-11-21, Mac, Release). `test: test_own_alias_warp_blep.cpp, test_own_alias_warp_blamp.cpp`. Block splits (32, 7+25, 1+31) give identical bits.
- **Half-band 2x oversampler (E7, `fx_oversampler.h`):** taps, gain and latency, symmetry and DC, passband ripple, stopband, round trip. `test: core/tests/test_own_alias_oversampler.cpp`.
- **Distortion with 2x oversampled ADAA (E8, `Distortion::Params::os2`):** up, `shape` twice per input sample at 2 fs, down, 10 Hz DC blocker at 1 fs; Bit Crush and Down Sample (4, 5) stay at 1 fs and are only delayed; latency `Distortion::kLatency` = 15 samples for every type (the impulse peak sits at 15 exactly). Alias against ADAA alone (drive 12 dB, `measured: 2026-11-21, Mac, Release, batch 5 merged tree`): type 1 -49.66 to -60.18 dB (-10.52), type 0 -83.50 to -89.78 dB (-6.27), type 9 -27.60 to -36.83 dB (-9.23), harmonics within 0.04 dB. Passband droop at 15 kHz (type 1, -30 dB drive): -6.35 dB off, -1.31 dB on. `os2` off is bit-identical to the code before E8 (all DIST-CHECKSUM / DIST-OS2-CHECKSUM lines equal the same code compiled on develop). `test: core/tests/test_own_alias_dist_os2.cpp (DIST-OS2-AA, DIST-OS2-DROOP)`.
- **Profile switch (E9):** `FxFrame::distOs2` = `kEconomyWarp` clear, i.e. the distortion runs 2x exactly where the oscillator warp runs 4x (tier high / medium / xl, or low with `warp=4x`) and 1x where `warp=2x` (tier low, any tier with `kEconomyWarp` set). With os2 on the module reports 15 samples and is never muted at mix 0 (the dry path is delayed to stay aligned); with it off the latency is 0 and the mix-0 mute stays. Bode in the same rack: 64 + 15. Tier low renders are bit-identical to before (DIST-LOW-CHECKSUM equal on develop). The default `Quality` (economy -1 on a tier with oversampling 2 or more) now runs os2: the offline distortion hash of `own_helper_thread` changed (`WAKE-SIGNAL-CHECKSUM dbde2dfe6294cac7` -> `79161dc9f9b5b8f7`) and is `dbde2dfe...` again with `economy = kEconomyWarp` (measured 2026-11-21). `test: core/tests/test_own_alias_dist_latency.cpp`.
- **Cost of the 2x distortion (Mac arm64, Release, 44.1 kHz, block 128, 32 notes, `synthyboy_tier_bench --modules --module-group fx`, indicative only, not the A17/A76):** the Distortion module on its own costs +6.75 us per block under `high` (os2 on) and +2.79 to +3.00 us under `high,warp=2x` (os2 off), 2.3x, 0.23 % against 0.10 % of the 2.902 ms block (3 runs, spread 0.2 to 3.4 %). Device numbers are still to be measured (A/B/A on the Key 61).
- **Latency test onset level:** the half-band is linear phase and rings before its centre (saw patch: 1e-5 from 8 samples early, 2e-3 one sample early, real onset 0.04 at +15), so an onset detector at 1e-4 reports +10 instead of +15; use 1e-2. A shifted comparison of a rendered signal against the unshifted one must start after the master volume smoother (about 960 samples after `prepare`; it sits after the latency delay and shows as a gain ratio 1.046 decaying to 1). `test: test_own_alias_dist_latency.cpp, test_own_fx.cpp fx_pool_order_rack_bypass_and_crossfade`.
- **The drive of the distortion is ramped across the control period** (gain, morph and divisor, linear), not stepped: a 30 dB jump made a step 15 times the steady sample step before, 1.00 times now. The ADAA state needs nothing extra: `adaa::step` and `stepShaper` re-make the stored integral at the last input when the gain (or morph) changes, so a gain that changes every sample stays a consistent difference quotient (cost: one more antiderivative per sample during the ramp). `test: own_distortion_drive_does_not_step (test_own_engine_fixes.cpp), fx_distortion_drive_ramps_across_the_period (test_own_fx.cpp)`. A still drive is bit-identical (all DIST checksums unchanged).
- **Shared decimation of the 4x warp path (`WtOsc::render`, unison):** the 128 tap decimator is linear, so the voices whose gain does not change inside the call (previous gain == current gain in both channels, `out = g * dec(x)`) are summed at the 4x rate weighted by their gains (L and R accumulators over the whole window: per voice history plus this period) and decimated twice instead of once per voice. From 3 such voices on; only the sequential 128 tap sum (tiers medium / high / XL: not `lowWarp`, not `fastMath`). **Not bit identical:** the float sums are in another order. A voice whose gain ramps (note start after the first period, level / pan / spread modulation, steal) keeps its own decimator, because a gain ramp applied before the FIR is a different signal (the gain would act about 16 samples early); so the result is the exact same maths per voice and only the rounding differs. The per voice history stays the raw 4x signal, unchanged layout, sizing and reset. Error against the per voice form: random-patch test (147 configurations of warp pairs x 1..16 voices x 3 motions, 4.5 M samples) max 1.19e-6 abs (-118.5 dBFS on a peak of +7 dBFS), at most 9.0e-7 of the block peak (-120.9 dB); 180 factory-preset variants (10 wavetable presets, osc 1 warp 1 / 3 / 7 / 11 / 18 / 27 x 3 / 7 / 16 voices, 3 tiers, note and chord, float32): max 4.8e-7 abs (-126.4 dBFS), -120.9 dB re block peak; an all-ramping render and any render with fewer than 3 steady voices stay bit identical. The factory presets render bit identical (none has a warp with 3+ steady unison voices on osc 1). `measured: 2026-11-26, Mac-less host x86_64 Release; test: core/tests/test_own_wt_osc_shared_decim.cpp`. Speed (host x86_64 scalar, `WtOsc::render` of a held warped note, A B A B A, us per 32 sample period): 4x exact 7 voices 40.5 -> 33.0 (-18 %), 16 voices 92 -> 66 (-28 %), 3 voices neutral; the Math economy 4x form (dot128) and the 2x 32 tap form showed no gain, so they keep per voice decimators. Whole-engine `tier_bench` (low,warp=4x worst) is too noisy on this host to resolve the difference. Device numbers (Cortex-A17 / A76) are NOT measured. HYPOTHESIS: the saving is larger on NEON.
