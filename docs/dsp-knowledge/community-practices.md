## Ranked list (benefit / effort)

| # | Practice | Benefit | Effort | Section |
|---|---|---|---|---|
| 1 | Ship a compact `TUI.json`, keep the one-element-per-line file in git | smaller file the host parses at load (2.47 MB vs 4.25 MB); community does it for big skins | very low | 2 |
| 2 | Remove unreferenced definitions (34 safe candidates) | smaller file, less to register, nothing lost | low | 2 |
| 3 | Add the SDK/community lint checks we lack: touch overlap, edge, orphan Q-Link, image present, Q-Link entry count | catches real defects before a device | low-medium | 5 |
| 4 | Move shared definitions to wrapped import files in the skin root | smaller diffs, tab files per owner; measured to resolve on Key 61 | medium | 1 |
| 5 | Freeze the parameter order (`params.lock`) and make the skin bind from names, not hand numbers | the 2026-11 renumbering of ~7000 handles cannot recur silently | medium | 3 |
| 6 | Keep the plugin-side UI rules as one checklist (UI-only params last and non-automatable, one display refresh per pass, debounce, tap events) | known host quirks written once | low | 3 |
| 7 | Measure a tab-reuse mechanism (`PageIndex`, shared tab root) before touching repeated tabs | would cut 25 near-identical tabs; unknown on device | medium (one measurement) | 1 |
| 8 | Release hygiene: SHA256SUMS, INSTALL text, version.xml uiversion, two-CPU zips from one tool | small | low | 4 |

Not adopted: skin sets / runtime skin switching (`OM/tools/make_skinset.py`: needs remove+insert, only for variants with different tabs; we ship one skin), `PartialDescription` (one tab repeated for the whole skin; SDK `docs/ui-reference.md:360-361`), the wrapper toolchain (`wrapper/vst2_wrap.c`, `gen_vst.py`, `layout.conf` DSL: for ports of existing engines; we use the SDK path).

## 1. How skins are structured and kept maintainable

What good skins do (all MEASURED-FILE unless noted):

| Skin | TUI.json size | tabs | local defs | instances | images used | instances/tab | defs reuse |
|---|---|---|---|---|---|---|---|
| stock AIR Reverb Pro | 0.23 MB | 4 | 20 | 112 | 27 | 28 | 5.6 inst/def |
| stock Visual EQ4 | 0.10 MB | 1 | 10 | 44 | 7 | 44 | 4.4 |
| stock Multiband Filterbank | 0.28 MB | 3 | 13 | 149 | 14 | 50 | 11 |
| stock Fabric XL | 0.88 MB | 18 | 85 | 415 | 62 | 23 | 4.9 |
| stock Sub Factory | 0.78 MB | 15 | 70 | 390 | 89 | 26 | 5.6 |
| stock OPx-4 (largest) | 2.27 MB | 31 | 156 | 1136 | 111 | 37 | 7.3 |
| community DX7 ("Dexed") | 0.64 MB | 9 | 12 | 545 | 157 PNG files | 61 | 45 |
| SynthyBoy `skin/TUI.json` | 4.25 MB (2.47 MB compact) | 37 | 539 | 4246 | 802 (79 MB as raw RGBA, 826 PNG files) | 115 | 7.9 |

(instances = `"componentData"` objects; images = distinct names in `image/filmStrip/onImage/offImage`; decoded size = width x height x 4 from the PNG headers, which is what the host's filmstrip cache stores, `OM/docs/NOTES.md:1110-1121`.)

- Stock skins: one root component per tab (tab version 3 with `componentName`: Fabric XL 18 distinct roots, Sub Factory 15; OPx-4 uses tab version 1 with the page inline for all 31). No stock skin reuses a tab root for several tabs. All import the shared factory files by relative path (`../../Generic/Generic Knob Overlay.json`, `../../AIR Components/AIR Generic Components.json`): `importFiles` is how they avoid carrying the overlay/knob definitions. Our skin is 1.9x the largest stock skin in bytes, 3.7x in instances, 7x in distinct images, 3-5x denser per tab. This is a measured size comparison, NOT evidence that it is slow: no source in the knowledge base measures tab-load time. The only load-cost facts are the filmstrip cache (every skin load decodes every filmstrip into `/var/tmp/filmstrips`, raw RGBA, never deleted; 195 MB per load for ~190 live knobs, 11 small files after reusing one strip: COMMUNITY/FACT-DEV `OM/docs/NOTES.md:1110-1121,1705-1722,1937-1945`) and the "Low Memory!" dialog it caused on a Live III. Practice from there: few distinct knob sizes/strips (checklist, `OM/docs/PORTING.md`), bars as `picture` option images instead of 128-frame strips, no skin image taller than 16384 px (`PORTING.md:150`).
- Generated, not hand-written: DX7 draws art and emits widgets in ONE function per tab (`KB/sources/mpc-vst-dx7/tools/skin_pages.py`, `op_page(op, fn, sub)` line 377: six operator tabs from one function, 68 widgets each, 26 KB each in `skins/TUI.json`), `make_tui.py` assembles `componentDefinitions` (12 defs) + `replacementStrings` (29) + Q-Links, and the art, widget coordinates and Q-Link rectangles come from the same call so they cannot drift (`OM/docs/SDK-PORTING.md:41-57`, :115-120; "keep the positions in sync" is the Plaits warning, `OM/docs/COMMUNITY_SKINS.md`). Model-72 does the same (`KB/sources/mpc-vst-model72/skin/tabs.py` = layout data, `make_skin.py` = drawing). SDK `tools/gen_ui.py` generates the whole skin from a 25-line `ui.json` (pages of controls by parameter NAME, `examples/SimpleSynth/ui.json`).
- Our mapping: `components/native/<name>/` recipes already are the "one function per widget"; the page layer (`shell-mpc/native_*_controls.h`) is the "one function per tab". The gap: `skin/TUI.json` is hand-edited and formatted (`scripts/skin-format.py`) with a hash baseline (`scripts/skin-baseline/TUI.keys.json`), so the six Env tabs (13221 bytes each) and 10 LFO tabs (11835 each) are 16 near-identical stored copies.
- Repeated pages, host mechanisms (SDK-DOC, all UNMEASURED on a device): (a) `PartialDescription` repeats ONE tab for the whole skin: unusable. (b) `PageIndex T, Q` handles bind a control to "this tab's Q-Link Q", so one definition can be reused by several tabs whose `Q-Links.json` entries map different parameters (`SDK/docs/ui-reference.md:1470-1476`); needs a Q-Link per bound control (16 per page), our tabs bind more than 16 handles. (c) Tab entries (version 3) name a shared root by `componentName`; no stock skin does it, but the DX7 community skin also keeps 6 copies. HYPOTHESIS: (b) cannot replace our `Parameter N` binding for tabs with more than 16 controls. One measurement would settle (b)/(c); rank 7.
- Imports (our measurement, Key 61, 2026-11-28, details in `skin-host-behaviour.md`): a WRAPPED import file `{"componentDefinitions":{version,importFiles,localComponentDefinitions}}` loaded from a relative path (`defs/lfo.json`) resolved its definitions; the UNWRAPPED SDK shape did NOT resolve; image paths inside an imported file resolve relative to the imported file's folder: a wrapped `lfo_defs.json` at the skin root resolved all 43 definitions and their images (tab identical to the inline skin), in `defs/` the definitions resolved but the images did not (PNGs are in the root). XL not checked. Community skins never imported their own files (all `importFiles: []`, `KB/sources/mpc-vst-dx7/skins/TUI.json`; `shadow_skin.py:1553` imports only the two factory overlay files by absolute `/usr/share/Akai/Content/Synths/` path), so our measurement is the first.
- Recommended split (rank 4): `TUI.json` keeps `tabs`, `info`, `replacementStrings` (no host mechanism splits those); shared definitions go to wrapped root files by family (`native_fx_defs.json`, ...), keys globally unique (between two imports the winner is undefined, `SDK ui-reference.md:304-306`); `validate_synthyboy_skin.py:121-122` must first learn to merge imports as the host does. Benefit is review/merge, not speed: nothing measures a load-time gain, and one XL freeze came from a definition change (`skin-host-behaviour.md`, freeze section). Pure move, byte-identical union, Key 61 first.
- Variants: tab sets cannot vary with `when=` (a hidden tab still shows, `OM/docs/SKIN_VARIANTS.md`); `when=` / `IndexedEnabling` (`SDK ui-reference.md` 7.2, 7.4) is the in-skin way to show modes. `Local/<range>/<id>` is a UI-only toggle shared by every widget on the page naming the same id (`ui-reference.md` 7.3): use it for show/hide panels that need no plugin state (SDK-DOC; no community skin we read uses it; not measured on a device).

## 2. Skin size, the host parse, dead definitions

- Compact JSON: `OM/tools/shadow_skin.py:1565-1569` writes a TUI.json over 8 MB compact because "the indentation alone is about 3/4 of the file, which MPC has to read and parse when the plugin loads" (COMMUNITY reasoning, no timing given). Ours: 4,254,542 bytes formatted, 2,466,627 compact (MEASURED-FILE, `json.dumps(separators=(",",":"))`; key order and duplicate keys need the repo's own `Obj` writer: `scripts/skin-format.py` already keeps both). Do it in the packaging step only (`scripts/build-mpc.sh` copies `skin/` with `cp -R`, line 235), so git keeps one element per line. Gain on the device is UNMEASURED (HYPOTHESIS: parse time scales with bytes); a Key 61 load stopwatch A/B settles it.
- Dead definitions: of 539 local definitions, 66 are never a component `type`, and 34 of those appear nowhere else as a quoted key (MEASURED-FILE: first candidates `compactNativeSmoothWithIndicator`, `compactNativeSmoothReadout`, several `NativeActive ...`). Find them with `grep -c '"<key>"'` equal to 1. Remove only after the build regenerates the baseline and the Key 61 loads the skin (a definition change once froze the XL project).
- Images: 802 distinct images, 79 MB as raw RGBA (stock OPx-4: 111 images). DX7 shipped 157 PNG files / 105 MB decoded in its folder. Frames x area x 4 per filmstrip is what the host writes per load (`NOTES.md:1118-1121`).
- Writer: SDK `gen_ui.py` and DX7 `make_tui.py` carry their own ordered-pairs JSON writer because the overlay data has DUPLICATE `version` keys (`SDK tools/gen_ui.py` header, `KB/sources/mpc-vst-dx7/tools/make_tui.py:15-50`): same as our `skin-format.py`.

## 3. Plugin code versus UI/skin data

- Parameter table generated from one source in a FROZEN order: `OM/tools/gen_vst.py:96-116` (`check_lock`: an existing key that moves fails the build, append only, `GEN_VST_RELOCK=1` deliberate break), DX7 `tools/gen_params.py:1-9` (table from `module.json` in `params.lock` order; a lock key missing from the module is an error), `OM/docs/SDK-PORTING.md:41-57,130,208`. Saved projects, automation, skins and Q-Links bind by INDEX. Ours: `git grep params.lock` is empty and `skin/TUI.json` has 7014 `Parameter N` handles; commit d28d24b9 "Parameter handles renumbered" and `scripts/validate_synthyboy_skin.py:82-90` (handle range + hash baseline) are the safety net. Adoption: a `params.lock` check in the build for released parameters, and (HYPOTHESIS, never run on a device: `Parameter/Named/<name>`, `SDK ui-reference.md` 7.1; no community or stock use found by grep) binding by name would remove the numbers from the skin entirely: measure on the Key 61 before relying on it.
- Skin text channel: display strings only. Text params are int params whose value text is the display (`formatValue`); the host re-reads text only when the VALUE changes, so flip a counter + `notifyHostParameterChanged` from the worker and call `requestDisplayUpdate()` once per pass (`SDK-PORTING.md:104-106,181-184,210-211`). `requestDisplayUpdate` also rebuilds the plugin UI page and re-lists programs: never periodic (`SDK docs/host-contract.md:58`, `SDK-PORTING.md:73-76`). `store()` without `parameterChanged` is silent: one `requestDisplayUpdate()` afterwards. The wrapper's 100 ms text poll and the deferred `audioMasterUpdateDisplay` are the older equivalents (`NOTES.md:359-389`, `:1161-1175`). Our own gating-on-text findings: `skin-host-behaviour.md`.
- UI plumbing parameters: appended LAST, `automatable = false`, flagged so they never reach the engine (`ui_open`, picture selectors, highlights: `SDK-PORTING.md:97-102,181`). Pick-list recipe from the community is for hosts where the native list opens empty; our measured host-list rules stay in `skin-host-behaviour.md` (lists keep factory behaviour).
- Debounce and timing, all FACT-DEV from the ports: parameter 0 is nudged by the host on every prepare, so a momentary/stepper there fires only after ~40-50 ms stable (`SDK-PORTING.md:73,161,212`); a tap on a lit toggle arrives as two events ~130 ms apart (ignore events within ~300 ms, `:213`); skip readback for ~300 ms after the last host change while a handle is dragged (`:259`); a momentary needs a 0..1 range or press reads as release (`:256`); fire momentaries on the rising edge. Compare with `shell-mpc/event_inbox.h` and the text-entry code before adding new ones.
- Gating: `IndexedEnabling/<i>/<n>/<h>` (visible only at step i of n; n must equal the step count of the controlling parameter's replacement strings), `RangedEnabling/<min>/<max>/<n>/<h>`, `NonZero/<h>`, `Local/<range>/<id>` (`ui-reference.md` 7.2-7.4). Community use: whole app screens as state machines of `when=` buttons (Plugin Manager: seven buttons on one spot, one visible, `OM/docs/COMMUNITY_SKINS.md`), kept in `additionalInvalidatingHandles` of a version-2 `bounds`; engine owns state, skin is presentation. That is also our separation; keep every state/enable decision in the plugin and expose it as one int parameter.
- Page switching without a reload: tab switching is host-owned; there is NO plugin route (no audioMaster opcode, no action handler navigates; `SubTab/<n>` is written only by a touch gesture; `KB/findings/host-tab-navigation.md`). Sub-tabs step only forward (`SDK-PORTING.md:115-118`). Community answer to "many pages": static background art per tab + live widgets on top, `when=` panels for modes, one LCD per tab.
- State of values not in params: `saveExtraState` text; suppress engine writes while the chunk loads (wrapped `effSetChunk`); keep the last state while the engine loads (`SDK-PORTING.md:165-168,247-249`).

## 4. Build, release, versioning

- Manifest: `plugin.json` (name, manufacturer, version, kind, uid, file32/file64) is the single identity; folder name must equal `"<manufacturer> - VST - <name>"` minus the illegal characters `"#@,;:<>*^|?\/`; `version.xml` `<uiversion>` must be <= 0.1.0.0 (`SDK tools/validate.py:36-45`, `docs/plugin-folder-format.md:25,121-129`). Keep name/uid/param order for in-place upgrades; a "beta" build gets its own name and uid so it installs next to the release (`SDK-PORTING.md:55`, :197-200).
- Packaging: Python `zipfile` with explicit modes, not `zip` (`SDK tools/package.py`, `SDK-PORTING.md:221`); `<slug>-<version>-mpc.zip`, INSTALL.txt, licences; Open MPC adds one zip per CPU (`-mpc-armv7.zip`, `-mpc-aarch64.zip`), `install.sh`/`uninstall.sh`, `SHA256SUMS`, `tested.json` (`OM/docs/RELEASING.md:1-40`). Our two-zip release already matches; adopt the checksum file and a generated INSTALL text if `scripts/package-mpc-release.py` lacks them.
- Binary checks before any device: ELF class/machine, newest `GLIBC_` symbol <= 2.39 (SDK) and an arm32 check of the real `.so`, only libs from the allowed list (`SDK tools/validate.py:36-40,225`; `SDK-PORTING.md:254-255`).
- Host-sim: `SDK tools/host-sim/host_sim.cpp` loads the native build, dumps `params.json` (read by `gen_ui.py` and `validate.py`), PASS/WARN/FAIL; CI builds and validates every example on three OSes (`SDK .github/workflows/build-examples.yml`). We already have `shell-mpc/host-sim-run.sh`; the part to copy is `host_sim dump` as the single source for skin-side parameter checks.

## 5. Validation and lint

- SDK `tools/validate.py:432-540`: `pageData.version == 1`, 1..32 tabs, no duplicate `fnKeyIndex/fnKeySubIndex`, every `Parameter N` within the plugin's count (from `host_sim dump`), every referenced image present in `Plugin Skins/`, `Q-Links.json` version 4 with one entry per tab, plus the binary and manifest checks. Duplicate JSON keys are read "last wins" (`load_json_last_wins`).
- Open MPC `tools/skin_check.py` (104 lines, run after every skin build): `TOUCH` two controls with overlapping touch boxes (>= 6 px each way) visible at once on one page, `EDGE` box outside 1280 x 628, `QLINK` Q-Link bound to a parameter no control of the page is bound to, `OPTS` a switch group missing options. Idea from saustin2010's `check_skin.py`. `tools/skin_compat.py` + `test_skin_compat.py` (140 lines, hand-built fixtures, no vendor file): a table of versions/field names per object role learned from stock skins; anything outside is flagged.
- Ours has JSON schema (`schemas/`, jsonschema required: a missing validator fails), handle range, hash baseline of the keys, display-binding check; it has NO touch-overlap, edge, orphan-Q-Link or image-present check (grep of `scripts/validate_synthyboy_skin.py`: none). Adding TOUCH/EDGE/QLINK/images is rank 3 and needs no device. Pattern worth copying from the generators' tests: build the fixture by hand, no vendor file (`OM/tools/test_skin_compat.py:1-12`), and a post-process step that FAILS when its target is missing so a generator change cannot silently undo it (`KB/sources/Shapey-MPC/vst/skin_post.py` header).
- Keep a "tested on" record per release (`OM tested.json`, device naming), which fits our `.hw-local/mpc-perf/` rule.

## What we do not need

Skin switching at runtime (`make_skinset.py`), the `layout.conf` text DSL and `shadow_skin.py` (they generate skins for ports of existing engines; our recipes already produce native components), the Plugin Manager catalog, ALSA/MIDI-out wrappers, favourites-in-file, external-engine bundles. Their lessons that apply (frozen order, one display refresh, debounce, UI params last) are in section 3.
