# Voice Control execution

## Facts

- The8-step sequence advances on engine note starts/recalls; each voice retains its sequence number. Length is1…8. Legato advances the step but retains that voice's random draws. All-sounds-off resets the counter. `source: core/engine-own/own_engine.cpp (startNote/reset), voice/voice.cpp (start/legatoTo/evaluateVoiceControl)`.
- RANDOM PAN is a unipolar0…100% variation depth. Sequence PAN is bipolar−100…100% position offset. Random DETUNE is0…100cents;10× multiplies only its random depth, not the sequence value. All selected sources, including generated/sampleNoise, add the same masked tuning offset; keyboard tracking controls only the keyboard-derived offset. `test: ownv_voice_control_noise_detune_and_random_tenfold`, including KEYTRACK on/off, targetOFF identity, zero-depth identity and3c×10=30c; generated noise is also waveform-identical to the equivalent explicit generator pitch.
- ENV scaling multiplies delay/attack/hold/decay/release time, not sustain/curve values. Per-voice ENV variation uses4^(step/100+random*depth/100), then global time percentage. `source: voice.cpp (evaluateVoiceControl/envSettings)`; `test: ownv_voice_control_envelope_scaling_random_and_sources`, `voice_legato_note_takes_the_envelope_scaling_of_its_step_without_modulation`.
- LFO Percent mode scales duration (inverse frequency); Rate mode scales frequency directly. Shared Free-run/mono LFO and globalRND clocks apply the factor in OwnEngine::controlTick. Local/poly and HOST/KEY voice clocks apply it in Voice, exactly once at their owning clock. `test: ownv_voice_control_scales_shared_and_local_lfo_clocks`:36comparisons across Hz/BPM/KEY, Percent/Rate, local/shared/mono/RND/HOST against explicit equivalent rate/division/transpose settings.
- TARGETS selects PAN/DETUNE applicability to A/B/C/Sub/Noise. CUTOFF and sequence/randomENV variation remain per-voice shared-filter/envelope controls, MOD1/MOD2 remain matrix sources, and globalENV/LFO scaling remains global. Turning every targetOFF does not disable those controls. `test: ownv_voice_control_targets_are_pan_detune_only` proves cutoff andENV still affect output with all targetsOFF.

## Per-period derivations (CPU review follow-up, 2026-11-26)

- **Oscillator part by field group.** `Voice::OscPart` (the ~45 keys of an oscillator that a voice derives once per epoch) used to be read again in full in every control period in which any key of that oscillator was modulated. Now only the field groups (`OscField`: route, wavetable, pitch, frame, level/pan, unison, warp, morph, library keys) of the keys the matrix touched in this period or in the period before (they fall back to their knob) are read again; each field is a function of the keys of its own group alone (`oscFieldMasks ()`; a key of an oscillator that no group claims maps to every group, a key the part does not read maps to none). The reference (`kOwnSavingVoiceControl`, `TickGlobals::referenceControl`) still reads the whole part every period. `test: voice_opt_osc_part_refresh_by_group_touches_every_key_alone` (every modulatable key of the three oscillators alone, three base values, touched / untouched / touched again with the epoch unchanged: the kept part equals the whole part read again, field for field, and the voice state and output equal the reference bit for bit; a deliberately wrong mapping of one key fails it), `voice_opt_voice_state_is_bit_identical` and the engine comparisons (random patches, factory presets, library oscillators).
- **Filter settings memo.** `fillFilterSettings ()` made up to four `exp2f` calls per filter and control period on arguments that rarely move (the key track, the voice control cutoff, the pan shift both ways) and `Voice::tick` one `powf` for `filterN.level`. A voice now keeps the results per filter under the bit patterns of their arguments (`FilterSetupMemo`, `lvlKey / lvlGain`); an argument of +-0 gives 1 without a call. The reference (`referenceControl`) calls them every period. A filter that is off keeps its level: a signal routed through an off filter is copied and scaled by the level in `Voice::render` (`runFilter`), so the level is not skipped for an off filter (the premise of the review item was wrong). `test: filter_setup_memo_gives_the_settings_the_calls_give_for_every_kind_of_argument` (300 000 argument sets with +-0, denormals, NaN, infinities, repeats), `voice_opt_voice_state_is_bit_identical` and the engine comparisons.
- **Render tail.** `Voice::render` read `paramIndex ()` (a guarded static) on every call: it uses the member `pidx`. A filter whose level is exactly 1 in the period before and in this one no longer runs `rampLerp` and two `mulBy` over its output: the ramp `a + (b - a) * t` is `1 + 0 * t = 1` for every sample and `x * 1` is `x`. The one value that would differ is a denormal `x` under flush-to-zero, and every reader of the output (`halfSum`, the meters, the peaks, `toTarget`, `addTo`) takes a denormal as 0 where the multiply would have, so the sound is the same on the device, in the flush-to-zero tests and without flush-to-zero; an x86 build with flush of results but not of inputs is not a target. The final `simd::addScaled (bus, m, 1.0f, n)` of each target is `simd::addTo` for the same reason. `OwnEngine::addGhosts` made the gain of every sample once per bus (4 times): once. The reference keeps all of it. `test: voice_opt_voice_state_is_bit_identical`, the engine comparisons and `voice_opt_engine_with_flush_to_zero_is_bit_identical` (tier low steals voices into ghosts). The review's `finiteBlock` item (scalar `isfinite` per sample) is in `fx/fx_chain.cpp`, outside this change.
- **A block whose generation moved without a change.** `OwnEngine::process` treated every move of the parameter generation as a new snapshot, also when no value and no content had changed (a host or the display writing the value a parameter already holds, `setPresetParams` of the same values, a tuning source set again): `snapEpoch` moved, `blockDirty` was true for the whole block, so the FX budget was evaluated again, the idle effect racks derived their settings again and the master volume, the route, the bus gains and the latency plan were recomputed (about 35-40 k Ir). Now a block that finds the loaded values, by bit pattern, and the content the same as the snapshot's takes the generation and changes nothing else (`statSnapshots`, `snapEpoch`, `baseEpoch` stay, `blockDirty` is false). `setParam` also does not move the generation for a stored bit pattern that is the same as the held one (the side effects of the key, a wavetable request or an effect type change, run as before). The reference is `kOwnSavingParamDiff`, which rebuilds on every move as before. `test: own_param_snapshot_a_write_of_the_held_value_derives_nothing_again` (seven keys of every consumer, a whole preset of the same values, the +0 / -0 pair, 60 mixed writes; the counters stay for the engine and move for the reference; every block equals the reference bit for bit), `own_param_snapshot_whole_preset_and_unchanged_values` (the same values again as a new generation); the new test fails on the code before (a snapshot counted for every write).
- **Voice count gain libm.** `updateVcg` made `pow (n_eff, -alpha)`, `log10 (n_eff)` and `pow (10, dB / 20)` in every control period while more than one voice sounds, on values that are the same period after period. The engine keeps the last results under the bit patterns of their arguments (`n_eff` and alpha for the first two, the stepped level in dB for the third). The reference is `kOwnSavingVcgCache`. `test: voice_opt_voice_count_gain_cache_is_bit_identical` (factory presets at five alphas and random patches with 4 to 16 voices, notes, steals and tier low / high, every block against the engine that calls them).
- **LFOs nothing reads: the newest voice only.** An LFO that no slot reads (`TickGlobals::usedSources`) feeds only the display, and the display reads the newest voice (the largest serial of the active voices, `TickGlobals::newestSerial`, found by `OwnEngine::controlTick` before the voices tick). The other voices still advance the clock, the age and the display position of such an LFO on the schedule the economy mode gave it (every period, or every fourth at tier low) but skip the shape and the smoothing (`Voice::lfoValue (..., advanceOnly)`); a voice that starts evaluates all of them. Audio of a fixed patch is bit identical: an LFO that a slot reads is never skipped, and the clock, the age and the phase of the skipped ones are those of the reference. What differs: (1) the display value of an unused LFO in a voice that is not the newest is not made (stale `lfoOut`, `src` and the smoothing state); if the newest voice ends in the last control period of a block, the voice that becomes the newest shows the value of its own last evaluation until the next block. (2) After an edit that newly routes an LFO that a voice skipped, the first evaluation starts the smoothing at the value instead of at the state of an earlier period (`lfoSkipped` marks it); the audio then differs from the engine that evaluated all, to the smoothing, and agrees again within a few smoothing times (measured on the voice rig: LFO 1, 80 ms smoothing, the first period after the edit differs by 0.187, 600 periods later by less than 1e-6). `test: voice_opt_unused_lfo_display_skip_keeps_the_sound_and_the_clocks` (100 random patches, 88 318 periods with a skipped LFO: every state field, the sound and the sources that are read bit for bit), `voice_opt_engine_unused_lfo_display_skip_sounds_the_same` (the engines with and without, fixed patches, notes, steals, releases), `voice_opt_engine_unused_lfo_display_readout_of_the_newest_voice_is_the_same` (the whole readout, `liveSource` and the LFO positions of the newest eight voices, block by block), `voice_opt_unused_lfo_newly_routed_starts_its_smoothing_at_the_value`. The reference is `kOwnSavingLfoDisplay`; the tests that edit a patch while voices sound run both engines with it set, since an edit that routes an LFO is not bit identical by design.
- **Display readout on demand.** `publishStats ()` and `writeReadout ()` (about 8.7 k Ir) ran at the end of every block although a display polls about 30 times a second, and a host without a display never polls. `copyReadout`, `voiceStats` and `setReadoutTargets` now set a countdown (`readoutDemand`, 256 blocks, as `requestMeters` sets `meterHold`); every block that writes takes one off, and a block with none left does not write. A display that polls keeps it going, so the readout of a polled engine is written every block exactly as before (the tests compare the whole `LiveValues` and `VoiceStats` against the engine that writes every block, polled one block in 11). After blocks without a write, the meters start from nothing instead of showing the memory of a peak from before the pause. Nothing is saved while a display polls: a cadence below one write per block would make a poll read data that is older by the blocks that were skipped (about 7 blocks, 20 ms, at one write in four), which is a decision about the display, recorded in TODO.md, not taken here. Also: the newest eight voices of the readout (eight passes over the active voices) are found in one pass (the same voices, ties on a shared serial taken by the first voice of the pool as before). `missingContent ()` is a state flag that any caller may read at any time, not a display value: its mask is published in every block (`publishMissing`), also in a block that skips the readout. Audio is unchanged. The reference is `kOwnSavingReadoutCadence`. `test: voice_opt_engine_readout_on_demand_is_the_same_while_it_is_polled_and_waits_when_it_is_not` (polled one block in 11: every poll equals the reference; 400 blocks without a poll: the statistics are not published, the sound is the same; the poll after it wakes the next block and the readout equals the reference apart from the meters; `missingContent ()` equals the reference's after a patch change in the unpolled stretch), the engine comparisons with a poll every block (the one pass).

## Evidence limits

- Tests are Mac offline source/audio checks, not MPC performance/device measurement.
- Exact Serum seed, steal/reset, nonlinear scaling and10× equivalence is not established by public documentation. Vital's official product material does not establish a direct matching Voice Control panel. See [the public-documentation review](../review/VOICE-CONTROL-REVIEW-2026-11-24.md).
- Dedicated all-envelope release/beats, random-lane independence and voice-steal audio regressions remain outside the focused fixes above; existing sequence/ENV-cache behavior is preserved.
