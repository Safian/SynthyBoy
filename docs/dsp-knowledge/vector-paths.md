# Vector (NEON) paths of the engine: scalar reference, bit-identity test, status

Inventory of 2026-11-26 (`grep` for `arm_neon.h`, `SB_NEON`, `SB_*_NEON`, `simd::` over `core/`, `shell-mpc/`, `tools/`, `bench/`). The contract of every row: the vector form computes in each lane the operations of its scalar form in the same order (separate multiply and add, true division, no reciprocal estimate, compares on the bit patterns, see [arm-denormals.md](arm-denormals.md)), so the samples are the same bits. Tests run on the Mac / on AArch64 hosts, and, added by this inventory, under qemu-user for AArch64 and ARMv7 (correctness only, no timings): `core/tests` builds them for both ARM forms (`-DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/<arch>.cmake`, `CMAKE_CROSSCOMPILING_EMULATOR=qemu-<arch>;-L;<sysroot>`).

## Rules the tests follow

- The tests are compiled with `-ffp-contract=off`; the **release build is not** (`-O3 -DNDEBUG`, no contraction flag; the source relies on `#pragma GCC optimize ("fp-contract=off")` in `dsp/simd.h`, `kernels.cpp`, `spectral.cpp`, `granular.cpp`, `sample_voice.cpp`, `filters-serum/src/filter.cpp`). A test that passes proves the form, **not** that the shipped object code has the same bits: that is `scripts/check-no-fma.sh` (below).
- 32 bit ARM: the NEON always flushes subnormals and produces the default NaN; tests run there in flush-to-zero mode (`core/tests/fp_flush_mode.h`) and compare a NaN as a NaN. AArch64 runs the default and the flush-to-zero mode.
- A quick / full split where a sweep is long (`SB_TEST_FULL=1`, entries `<name>_full`, label `slow`).

## The shipped object code (`scripts/check-no-fma.sh`)

`scripts/check-no-fma.sh [--arch arm32|arm64|all] [--build-dir DIR] [--no-build]` disassembles (`objdump -d`) every object file of the audio libraries of a Release cross build and lists, per function, fused multiply-add (`fmadd fmsub fnmadd fnmsub fmla fmls`; `vfma vfms vfnma vfnms`) and reciprocal / reciprocal square root estimates (`frecpe frecps frecpx frsqrte frsqrts`; `vrecpe vrecps vrsqrte vrsqrts`); `vmla.f32` is counted separately (not fused: the product is rounded first). Exceptions are documented in `scripts/check-no-fma.allow`. `measured: 2026-11-26, GCC 13.3 cross compilers, Release, 75 object files per architecture`.

- **ARMv7 (Key 61, `-march=armv7-a -mfpu=neon`): 0 fused instructions, 0 estimates in all 75 objects; 394 functions use the non fused `vmla.f32` / `vmls.f32`.** The VFPv3 / NEON of that target has no fused operation and the sources have no estimate intrinsics. The check passes (`--arch arm32`, exit 0). Note that `-mfpu=neon-vfpv4` (or any VFPv4 / `-march=armv8-a` AArch32 build) would fuse: the toolchain file pins the FPU.
- **AArch64 (XL): fused operations in the scalar helpers that are defined before the first include of `dsp/simd.h`.** The pragma of `simd.h` works from the point of inclusion on; `voice.cpp` includes `voice.h` -> `lib_osc.h` -> `warp_adaa.h` -> `warp.h` first, so `warpPhase`, `warpSample`, `warpadaa::step / stepTanh` and `fastmath::sinCycles` are compiled contracted (`voice.cpp.o`: 25 x fmadd + 11 x fmsub in `warpPhase`), while `WtOsc::warpPhase4` (`wt_osc.h`, after the pragma) is not. `WtOsc::render` calls the out-of-line `warpPhase` for the samples that do not take the lane form (the odd last samples at 2x, warps without a lane form) and `warpPhase4` for the others. `measured:` the out-of-line `warpPhase` against `warpPhase4`, 800 000 lanes each (qemu-user AArch64, release flags): the phase differs in 22 367 (Sync), 182 123 (Bend), 169 479 (Formant), 68 024, 55 810, 80 598 lanes, the Formant window in 844 at tier low. One unit in the last place of a phase (6e-8 cycle), inaudible, but the NEON form and the scalar form of the same oscillator are **not** bit identical on the XL, and no test sees it because every lane test is built with `-ffp-contract=off`.
- **Engine level, exploratory (not a clean oracle):** the same ten factory presets (`sync_saw_raw_bass bend_formant_growl formant_pop_pluck stutter_grain_kit spectral_vowel_freeze fm_digital_lead twin_warp_lead chorused_saw_solo bell_fm_ripple_lead screaming_sync_lead`, `--float32 --hash --hold 0.4`) rendered by the NEON build and by an `-DSB_NO_NEON` (scalar) build of AArch64 under qemu-user, release flags. Tier high: 6 of 10 hashes differ (all four warp presets, `bell_fm_ripple_lead`, `stutter_grain_kit`); tier low: 8 of 10 (the low tier also changes the Digital pair loop on purpose: the scalar build takes reciprocals there, `classic_filters.h`). `spectral_vowel_freeze` and `formant_pop_pluck` are equal at both tiers. The warp presets are what the contracted `warpPhase` predicts; the differences of `bell_fm_ripple_lead` and `stutter_grain_kit` were **not** bisected (HYPOTHESIS: the same contraction in another scalar helper; the granular and sample kernels themselves are equal vector against scalar in their own tests). `measured: 2026-11-26, qemu-user, no device`
- Proposed fix (not applied: outside the scope of this task, and it changes the last bit of the XL output, so the baselines / checksums and a device check follow): `-ffp-contract=off` on the audio library targets (`synthyboy_core`, `synthyboy_sampleosc`, `synthyboy_granular`, `synthyboy_spectral`, `synthyboy_filters_serum`), with the pragmas kept; then `check-no-fma.sh --arch arm64` must pass with the allow list shrunk to the control-rate scalar code.
