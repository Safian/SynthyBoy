# FilterResponse: answers to the independent review

Review: `REVIEW.md` of branch `agy/review-filter-response` (commits `aeec2ee`..`083aeb4`). One line of reasoning per finding; the tests named here are in
`core/tests/test_own_filter_response*.cpp` and `tools/filter-response/CMakeLists.txt`.

| Finding | Decision | Reasoning / where |
|---|---|---|
| A (voice refactoring) | not a defect | The review itself confirms `Voice::tick` is bit identical; the regression and golden tests stay green. |
| A-1 negative modulated resonance snaps back to the knob | **fix** | `Request::cutoffHz` / `resonancePercent` are `std::optional<float>` (no magic value); a set value is used as is, the filter clamps (like the voice). Tests `..._negative_modulated_resonance_does_not_switch_the_override_off`, `..._each_override_alone_replaces_only_its_knob`. |
| A-2 no global modulation of filter targets without a voice | **fix** (engine, readout only) | `OwnEngine` evaluates, for an idle engine with readout targets, the slots whose sources have a value without a voice (macros, mod wheel, aftertouch, pitch wheel, last velocity / note, fixed) into a separate delta array that only `writeReadout` reads (`EvalContext::sourceMask`); slots on per voice sources (LFO, envelope, random) are skipped and the knob value stays. The audio path is untouched (test `..._idle_readout_leaves_the_sound_unchanged`: bit identical with and without a subscription; goldens green). Tests `..._readout_without_a_voice_follows_macro_and_mod_wheel`. Header text corrected. |
| A-3 stereo modulation and other parameters lost | **decided + documented + tested** | Filter pan: shown as the power mean of both channels (test `..._filter_pan_shows_the_power_mean_of_the_two_channels`, 0.0000 dB against the two single channel curves). A modulation with the stereo flag: the readout carries the left lane, so the display shows the left lane (test `..._a_stereo_modulation_shows_the_left_lane`). Modulation of drive / blend / mix / var etc. is not in the readout: the display shows the knob values of those (stated in the header); the cutoff and resonance are the live parts. |
| B-1 24 dB analog differs 1.13 dB between 44.1 and 96 kHz | **not a defect of the method** | The filter is a bilinear (TPT) design: a frequency f at rate sr acts as tan(pi f / sr) / tan(pi fc / sr). Mapping the 44.1 kHz curve through that warp onto the 96 kHz curve agrees to 0.0002 dB (measured in the test), so the measurement is exact and the display shows what the engine does at that rate. The test now asserts the raw spread is in 0.8 .. 1.3 dB (measured 1.128 dB at 4.97 kHz) AND the warped agreement < 0.05 dB. |
| B-2 output offset of MG Dirty swamps the FFT | **fix** | The response to silence is measured and subtracted when the filter has an output offset (detected on 1024 silent samples; it is run only until it settles). The curve is the small signal response around the operating point (+17.6 dB at 20 Hz for var 50 %, the gain of the "pain" stage, not +60 dB). Test `..._output_offset_of_a_model_does_not_swamp_the_curve`. |
| B-3 time varying models (ring mod, sample and hold) | not a defect (inherent) | No transfer function exists for them; the display shows the magnitude of the response to an impulse = the first sample of a note. Stated in the header. |
| B-4 60 dB jump with `includeLevel` | **fix** | The floor (-120 dB) is applied before the level is added; test `..._level_is_added_after_the_floor` (silent end = floor + level, stopband monotone). |
| B-5 NaN / Inf / UB | **fix** | Validation of fMin / fMax / overrides / every parameter of the filter group (false and 0 dB when unusable); snapshot values clamped to the knob range before integer casts; reference note clamped to 0 .. 127; sample rate made usable in the constructor (NaN, <= 0: 48000). Tests `..._unusable_arguments_...`, `..._unusable_snapshot_values_...`, `..._sample_rate_is_made_usable`. |
| B-6 CLI exit codes | **fix** | Missing value, non-number, `fmin <= 0`, `fmax < fmin`, bad `--set` value all give exit code 3 with a message and no output; documented in the tool header. CTest cases `synthyboy_filter_response_cli_*`. |
| B-7 clean mode invisible / saturating drive | not a defect, documented | -24 dB before and +24 dB after cancel on a linear response; saturating drive shows its small signal gain. The header said "clean mode is in": corrected; test `..._clean_mode_does_not_change_the_small_signal_curve`. |
| B-8 sample rate clamp, `lengthFor` doc | **fix** | The constructor clamps to 22050 .. 192000 Hz (what `filters::Filter::prepare` runs at) and `sampleRate()` returns it, so bin frequencies match the DSP; the length text in the header is exact now (>= sr / 3, 8192 .. 65536). |
| B-9 (1) interpolation below the first bin | **fix** | Below one bin width the response is evaluated directly (DFT at exactly f); a 12 dB high pass keeps 12.0 dB per octave between 0.5 and 2 Hz (the DC interpolation gave about 6). Test `..._below_the_first_bin_keeps_the_slope_of_a_high_pass` (also continuity across the first bin). |
| B-9 (2) double filter run when pan != 0 | **fix** | One run gives both channels; the output is bit identical to before (same samples). |
| C-1 `paramIndex()` built inside the first `compute()` | **fix** | Built in the constructor. |
| C-2 `readoutIndices(nullptr)` | **fix** | Null check; test in `..._unusable_arguments_...`. |
| C-3 mutable calibration statics | **fix** (trivial) | `static constexpr` with the same values (nothing writes them): no race possible, same code. |
| D-1 `finiteAndSane` tautology | **fix** | Replaced by `hasSignal` (range AND the curve carries a signal: > -100 dB somewhere) with the reason in the comment. |
| D-2 `flat` curve never checked | **fix** | Checks: no peak, and the resonant curve is more than 10 dB above it at the cutoff. |
| D-3 CLI test only checked the first line | **fix** | The CLI test checks all 64 lines (count, first and last frequency, every gain finite) via `tools/filter-response/check_cli_output.cmake`. |
| D-4 uncovered branches | **fix** | `includeLevel`, pan, `numPoints == 1`, single overrides, `resonance = 0` boundary, state leaking between patches, refill before the `filter = 3` call, 24 dB steeper than 12 dB, band pass peak at the cutoff, thread start handshake (the audio thread has run before the compute loop starts), `crossing12` now really interpolates, `readoutIndices(2)` / invalid. |
